# Finite owned-original host preparation

This source adds an explicit `--offline-original-only` profile to the existing host AUTO_READY entrypoint. It uses the already-owned finite original-text catalogue for delivery and reserve generation, with no paid generation or provider fallback. It does not install a schedule, authorize production writes or establish complete hosted workflow equivalence.

Default execution remains an offline plan. Apply requires the existing protected READY-write approval and competing-Actions-disabled attestation, plus the independent protected `AUTO_READY_OFFLINE_GENERATION_APPROVED` control. Beauty also requires its existing activation approval. Caller variables cannot grant these permissions. The deployment environment writer carries the new boolean only from the validated protected source; absent is false and malformed values block candidate creation.

The inventory CLI accepts this profile only for confirmed single-account ordinary text Apply. Delivery and reserve calls both force the existing offline generation router. Bank allocation remains capped and existing Bank tabs must already exist; this mode never creates or migrates the operational schema. Catalogue exhaustion is an explicit failure and prevents further generation attempts during that account run, without falling through to a paid provider. A 24-hour host run uses the existing explicit offline Bank profile for the reserve stage.

Existing account/persona checks, historical and semantic duplication controls, draft/activation preflights, strict review/approval, slot suitability, publisher validation and readback remain in place. Deployment, shared Sheets and account locks span all stages. Provider credentials are removed and posting/media execution disabled. Later success cannot hide a failed reserve stage. The success marker identifies finite-catalogue preparation and explicitly states that paid generation and posting are false and full hosted equivalence is unproven.
