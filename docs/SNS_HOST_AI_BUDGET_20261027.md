# Durable host API attempt budget

This source-only guard is additional to existing JSON and Sheets budgets. It does not authorize paid usage or enable a generation schedule. The strict host-generation profile remains unavailable until its full operational prerequisites are verified.

`reserve_host_ai_attempt(account_id, operation)` is called immediately before every actual HTTP attempt in reference rewriting/semantic judging, generic Gemini generation and hybrid text/multimodal generation. Retries and model fallback consume separate reservations. Existing provider/schema/thinking/output/semantic checks remain authoritative. A budget refusal propagates instead of returning a draft or trying another provider. Cache hits and mock paths make no transport reservation. Earlier JSON/Sheets reservations are retained; an extra refusal may conservatively consume an earlier allowance without making a provider call.

Strict mode requires `SNS_HOST_AI_BUDGET_REQUIRED=true`, a canonical protected private budget directory, a fresh run identity, an explicit managed account and an immutable release identity. The durable run is bound to one account/release. Fixed request ceilings are 20 per run, 40 per JST day and 1,000 per JST month, globally across accounts; these are request ceilings, not a currency-spend meter. Reservations are never refunded. File locking and an immediate SQLite transaction serialize subprocesses, FULL synchronization plus fsync completes before HTTP, and malformed schema/integrity/permissions/time/context fail closed. Existing stronger budgets still apply.

Reservations never create a ledger automatically. A separate operator must independently audit existing current-day/month usage, explicitly confirm those mandatory baseline values and initialize the private ledger. Initialization refuses an existing database. Default CLI only describes an offline refused/uninitialized plan and grants zero capacity. Reinitialization, using another directory, restoring stale accounting or tampering under the same trusted UID cannot establish valid spending continuity; operations must preserve one canonical ledger and account for recovery. No production initialization or baseline attestation has occurred.

Vision's caller account is forwarded from the explicitly selected source target or review record through local understanding into transport metadata; account strategy, source metadata and transcripts still do not enter the observation prompt. Empty or foreign account scope remains refused in strict mode; scope is never inferred from the token or another account. Ledger refusal propagates out of visual understanding rather than becoming accepted visual evidence. Media permission/provenance/publish checks are unchanged.

Ledger-only tests cover fresh-process concurrency and persistent global/run counters, account/release mismatch, audited baseline exhaustion, JST period boundaries and rollback, corrupt/foreign schema, permission/symlink/hardlink/owner/file synchronization failures, and no implicit initialization. Mocked transport tests cover each retry/fallback attempt, draft+judge accounting, denial before HTTP, judge denial rejecting the draft and legacy/mock/cache behavior. Final combined Mac quality gate PASS: 1,098 regression scripts, workflow safety 619/619, source compilation, fatal Ruff, diff and history secret scan; additional pytest 169/169 PASS. Existing exclusions are unchanged. Working-tree secret scanning is also required before publication. No provider calls, production ledger changes, token rotation, SNS posting or schedule cutover are part of this patch.

Transport privacy hardening also moves the generic Gemini key from its URL into the supported authentication header and disables redirects for authenticated generic/reference calls. Chained transport exceptions and unknown provider block reasons are not emitted in error packets. Header support is documented in the [official Gemini API reference](https://ai.google.dev/api). Request content, model, thinking/output and semantic gates are unchanged.
