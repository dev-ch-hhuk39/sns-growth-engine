# Guarded local host automation source

This batch closes specific source gaps without installing schedules or changing production consent. Existing operational Actions remain enabled until equivalent authenticated execution is independently proven. Protected PR CI remains mandatory.

| Component | Implemented behavior | Remaining boundary |
|---|---|---|
| Publisher | Acquires deployment lock before reading release/config; validates and uses one immutable revision for authority and execution | Full runtime rollout and signed publishing authorization remain separate |
| Environment writer | Preserves existing host-only aftercare/preparation consents and exact acquisition scopes; caller inputs ignored, absent flags false | Does not grant new consent or retarget a release-bound approval |
| AUTO_READY host | Default offline plan; confirmed read-only preview; explicit approved-inventory reuse or independently approved finite owned-original generation under continuous deployment/Sheets/account locks | Paid/full generation refuses; no complete hosted equivalence or live proof |
| Acquisition host | Default offline plan; explicit bounded X/YouTube metadata acquisition through existing failsoft source CLI and rights/provenance rules | Threads/TikTok, approved Beauty acquisition and complete hosted parity deferred |

`run_buffered_auto_ready_host.sh` accepts exactly one managed account. Apply requires protected `AUTO_READY_WRITE_APPROVED` and `AUTO_READY_ACTIONS_DISABLED_ATTESTED`; Beauty also requires its existing activation approval. Explicit reuse and finite owned-original modes are supported. The latter also requires protected `AUTO_READY_OFFLINE_GENERATION_APPROVED` and uses the existing offline-only generation router for delivery and reserves; catalogue exhaustion stops generation without paid fallback. See `SNS_OFFLINE_ORIGINAL_HOST_20261027.md`. Existing draft preflight, activation/kill-switch policy, inventory validation, bounded Bank allocation/reuse, strict ready-only loop and final validation remain mandatory. Bank failures cannot be hidden by later success. Provider credentials are scrubbed and posting/media flags disabled. Paid/full-generation host execution remains unavailable pending verified canonical budget initialization, protected authorization and complete operational proof; the additional durable API guard alone does not grant paid execution.

`run_buffered_acquisition_host.sh` requires one account, approved/reference-only scope and x/youtube platform, with a per-source cap of 1–30. Apply requires protected write consent, competing-scheduler attestation and exact account/scope/platform/release matching. Beauty is reference-only with its separate activation control. Existing source-specific author/permission selection and critical persistence errors remain authoritative; no download/cut/upload/publisher is invoked. All three locks cover read-only preflight and the single mutation invocation. There is no wrapper retry after ambiguous/failed writes.

Both entrypoints default to an offline plan without loading protected configuration. Protected runtime reads reject invalid file boundaries/permissions; acquisition and READY preparation clear caller credential/import aliases before loading the fixed source. Executable venv interpreter symlinks remain supported as in the existing deployment health contract. Shell tracing is disabled before secrets are loaded, including inherited debug tracing. No runtime credentials are inspected by development tests.

The environment writer preserves the existing four aftercare controls, the three READY controls, the two acquisition controls and exact acquisition scope strings only from its validated protected source. Absent booleans stay false; malformed booleans, account/scope/platform enums or release identities block candidate creation. A preserved acquisition release approval intentionally remains tied to its old SHA after deployment, so a new release is never automatically authorized.

Offline shell integration tests exercise real entrypoints with isolated fake runtimes, scoped child capture, symlink interpreters, credential tracing/spoofing denials, immutable-pointer races, continuous advisory locks and failure propagation. Source-only results cannot establish live inventory, source access, scheduler replacement, publication or metrics acceptance. Full regression and final validation are recorded before delivery.
