# Account-scoped host metrics aftercare

The host aftercare entrypoint now supports the three managed accounts one at a time. Beauty requires independently protected activation and `AFTERCARE_BEAUTY_METRICS_APPROVED` before either confirmed read-only or Apply execution. Metrics writes additionally retain their existing write consent and competing-Actions-disabled attestation. Optional measured-strategy writes and existing-Bank reuse retain separate approvals and manual-only restrictions. The new Beauty boolean defaults false and is preserved by deployment only from the validated private host source; caller/CI variables cannot grant it.

The entrypoint loads only the fixed runtime shared configuration, rejecting a caller-selected substitute, linked shared directory or invalid file ownership/mode. All supported Sheets credential/ID aliases, Threads account credential variables and token-store override, Beauty controls and Python import overrides are cleared before protected configuration loads. Missing protected Sheets values cannot be filled from the caller. Selected Threads credentials still use the existing account-specific resolver; no cross-account fallback is introduced.

Before children run, paid provider aliases, mock flags and publish/media controls are disabled. The entrypoint pins one immutable release under the global deployment lock, rejects linked required scripts, changes to that release directory and holds shared Sheets/account locks continuously through previews, bounded metrics collection and optional feedback stages. Child stdout/stderr stays in a private temporary directory; public receipts contain fixed stage/status fields. Any failed stage stops dependent work without blind retry; already-completed remote writes are not rolled back. Temporary child diagnostics are removed on exit.

Offline plans remain offline and grant no live capability. The wrapper explicitly reports full hosted-workflow equivalence as unproven. This patch installs no scheduler, enables no approval, performs no provider request or Sheets write and cannot prove timed 24h/72h/168h observations or three-account live acceptance.

Focused checks: seven actual-shell integration tests cover three-account forwarding and the real config-loader alias precedence, continuously held OS locks, injected credential/mock/approval denial, private child output, immutable-pointer race, linked-worker refusal and fail-stop behavior. Existing host policy16 and environment lifecycle22 tests plus Beauty worker/account contracts pass. Final combined regression and secret scans are recorded before delivery.
